## 2026-03-15 - [Avoid Thenable Database Mock Objects in Async getDb Helpers]
**Learning:** In async functions like `await getDb()`, returning an object that has a `.then` property causes the JavaScript promise/async-await runtime to treat the object as a "thenable" and automatically resolve/unwrap it. If the mock database object itself has a `.then` method designed for mock query chains, this automatic unwrapping will execute the `then` method early, returning its resolved value (often an empty array or single row mock) instead of the database instance itself. This leads to confusing `TypeError: db.select is not a function` errors inside the production helper because `db` has been resolved to the mocked row/array data.
**Action:** When mocking chainable database query builders, do not make the root database object thenable. Only make the final query builder steps (such as the return values of `select()`, `insert()`, `update()`, and their chains like `limit()`, `where()`) thenable. This ensures the database helper returns the database mock intact, while queries can still be awaited properly.
