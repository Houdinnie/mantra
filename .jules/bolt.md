## 2026-08-01 - Mocking Drizzle Query Chains and In-Memory Aggregation Anti-Pattern
**Learning:** In-memory aggregation of database records (e.g., retrieving all user sessions and sorting/reducing them in Node.js) is a major performance anti-pattern (O(N) data transfer and memory usage). We can easily convert these to O(1) by utilizing Drizzle ORM native aggregation helpers (`count`, `sum`, `max`). However, when unit testing these database functions with Vitest, mocking chainable query builders requires ensuring that the top-level database instance is NOT thenable, while only the final query builders are thenables. Otherwise, async wrappers like `await getDb()` prematurely resolve the db mock as a promise, causing TypeError runtime crashes on nested chain calls.
**Action:** Always prefer native SQL aggregate functions from `drizzle-orm` at the top of the file over loading rows and sorting/aggregating in memory. When mocking database instances for these queries, set up mock query chains where `db.select().from().where()` are mock-chained and resolve correctly, and never make the main `db` instance thenable.
