## 2026-03-04 - [SQL Aggregation over In-Memory Computation & Drizzle Query Builder Mocking]
**Learning:** Performing in-memory computations on large datasets (such as fetching all chat sessions to calculate total counts, sums of messages, or sorting to find the latest active date) incurs O(N) or O(N log N) complexity, loading excessive rows into Node memory. Moving this calculation to native Drizzle SQL aggregate functions (`count`, `sum`, `max`) results in a massive O(1) optimization. When testing these database queries, we must ensure the main database instance mock itself is not a thenable (to avoid premature Promise resolution inside async database helpers like `await getDb()`), while returned query builders must be thenable to correctly handle chained method sequences like `.select().from().where().orderBy().limit()`.
**Action:** Always offload counting, summation, and extrema retrieval to native SQL aggregation functions in Drizzle. During testing, mock query chains using non-thenable root databases combined with thenable, chainable query builders.
